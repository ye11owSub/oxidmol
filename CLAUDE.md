# OxidMol: working notes for Claude

A PyMOL-inspired molecule viewer. The renderer is written in Rust on wgpu and exposed to Python through PyO3 as the module `oxidmol.lsd`; the UI is PySide6.

## Commands

```bash
source .venv/bin/activate                  # REQUIRED before cargo test, see "Pitfalls"
uv sync --group dev --no-install-project   # dependencies without building Rust (same as CI)
uv run --no-sync maturin develop           # build the extension into .venv (after every Rust change)

cargo fmt -- --check
cargo clippy --all-targets -- -D warnings  # warnings are errors in CI
cargo test                                 # Rust tests, including the GPU tests

ruff format --check python/ && ruff check python/ && mypy python/
QT_QPA_PLATFORM=offscreen pytest -m "not gpu"   # what CI runs
pytest -m gpu                                    # needs a display and a GPU

oxidmol                                    # run the app (RUST_LOG=warn hides the naga/wgpu debug noise)
```

`/check` runs all of the above except the GPU and app launch steps. Run it before finishing a task: CI fails on any of them.

## Layout

```
src/
  lib.rs              PyO3 module `lsd`, logging setup
  core/               Molecule, Chain/Residue/Atom, FlatAtom, sphere mesh; PDB/mmCIF loading (pdbtbx)
  renderer/
    state.rs          State = GpuContext (window + surface) + Scene
    gpu_context.rs    instance/surface/adapter/device; everything returns Result<_, WgpuError>
    scene.rs          Scene: camera, pipeline, depth, objects; render() into any TextureView
    pipeline.rs       PipelineBuilder (takes the shader as a WGSL string)
    scene_pipeline.rs builds the main pipeline; the shader is embedded with include_str!
    test_support.rs   (tests only) windowless device, pixel readback, validation error scope
  python/             PyO3 wrappers: WgpuRenderer, PyMolecule
  utils/              errors, qt_window.rs (QWidget.winId() -> raw-window-handle), logging
  shaders/shader.wgsl
python/oxidmol/
  app.py, settings.py
  ui/                 main_window, scene (WgpuWidget), object_panel, command_bar, menu/, theme.py
  dsl/                command grammar (lark) and transformer
  utils/              loading, cache, fetch
  lsd/__init__.pyi    type stubs for the Rust module
tests/data/           PDB/CIF files used by tests
```

## Pitfalls

- **`cargo test` does not link without the `.venv` activated** (`-lpython3.9`, it picks up Xcode's Python). Always `source .venv/bin/activate` first.
- **Rebuild with `maturin develop` after every Rust change**, otherwise the Python tests and the app use the old extension.
- **wgpu 30 requires a display handle on the instance**, even on Metal (`MissingDisplayHandle` otherwise). It is passed through `QtDisplayHandle`.
- **Use the `directx` projection, not `vulkan`.** The wgpu NDC is Z in [0, 1] with Y up; `vulkan` flips the image. There is no OpenGL-to-wgpu matrix any more.
- **GPU tests are skipped silently when there is no adapter, and a skip is a pass.** `OXIDMOL_REQUIRE_GPU=1` turns the skip into a failure. CI runners most likely have no GPU.
- **The windowless GPU tests do not cover the window.** `GpuContext` and the surface are only checked by launching the app and by the `gpu`-marked widget test.
- **Renderer errors are `RuntimeError`, not panics.** Catch `Exception` in Python, not `BaseException`.
- **Linux: only X11/XWayland.** Native Wayland is not supported yet. Manual testing so far was done on macOS only; Linux and Windows are not tested by hand.
- **PySide6 is capped at `<6.12`** because 6.12 has no wheels for macOS 13. Do not upgrade it without checking that the platform support has changed.
- **`approx` stays on 0.5** (0.6 is still a release candidate). `pollster` was replaced with `tokio` (feature `rt`).
- **Every molecule load adds an object instead of replacing the previous one.** Known, not fixed.
- **The extension uses the stable ABI (`pyo3/abi3-py312`)**: one wheel per platform works for every Python >= 3.12. After switching Python versions or build modes, delete stale `python/oxidmol/lsd.*.so` files: an old `lsd.cpython-*.so` is imported before `lsd.abi3.so`.
- **Releases**: release-plz runs in git-only mode (versions come from git tags, nothing goes to crates.io). A new tag starts the wheel builds and the PyPI upload in `CI.yml`.
- `.github/workflows/CI.yml` is marked as generated by maturin; `maturin generate-ci` overwrites manual edits. Wheels are built only for tags and manual runs.
- The README and the module description in `lib.rs` say "PyQt6" although the project uses PySide6 (not fixed).

## Conventions

- Rust 2021, `cargo fmt`, no clippy warnings. Use a targeted `#[allow(dead_code)]` for intentionally unused code (the idiom already exists in the project).
- `unsafe` needs a `SAFETY:` comment that states the guarantee.
- Python: ruff (line length 120, rule set in `pyproject.toml`), strict-like mypy (`disallow_untyped_defs`); type the Qt event arguments (`QShowEvent` etc.).
- UI: styles live only in `ui/theme.py` (palette plus one `STYLESHEET`). Widgets get an `objectName` and no inline QSS. The exception is the per-object dot color in `object_panel.py`, which is dynamic. Get the monospace font from `theme.mono_font()`, never by family name.
- Tests: Rust tests sit next to the code (`#[cfg(test)]`); Python tests are in `python/oxidmol/tests` with the `ui` and `gpu` markers declared in `pyproject.toml`. Check a new test against a deliberate breakage: break the code temporarily and make sure the test fails.
- Commits: `release-plz` and `git-cliff` build the changelog from conventional commits only (`feat:`, `fix:`, `refactor:`, `perf:` ...); other commits are filtered out (`filter_unconventional = true`). Do not commit unless asked.
